# ALO Learning Journey · working-tree readiness review

**24 November 2026 · Decision: NO-GO for production.** This is a repository and isolated-runtime review, not an attestation about the live service. No credential values appear in this report.

## 1. Executive summary

Repairs were made to the existing application, not a replacement: credential handling, tenant role delegation, MFA and session handling, account provisioning, public enquiries, media cleanup, hosted AI policy, and release checks. The previously red route test is green without weakening it. **154 unit/regression tests passed.** A real local photo upload produced a downloadable MP4 and Bengali subtitle; a real browser exercised the administrator credential flow. These are narrower claims than “every module works.”

Do not ship this checkout as a production artifact. The environment could not complete the native Prisma installation. No MySQL-backed acceptance run of the changes, production-schema reconciliation, provider delivery test, or restored-copy rehearsal was possible here. The credential incident remains open, even after the backup file is removed from the working tree.

## 3. Initial audit findings

The root build serves the ALO admin workspace and MarketingOS from the **same** Next.js server. It is not the historical standalone SQLite CRM. There are 5 page entry points, 316 API route files and 154 TSX files under `src/components` (including shared UI). The old inventory counted 2 pages and 78 API files. The [new inventory](../docs/ROUTE-INVENTORY.md) lists every root page, API path and explicit HTTP method, including aliases and dynamic segments. Sidebar views are components, not separate URLs.

ALO uses NextAuth credentials + configurable administrator OTP and an 8-hour admin session; MarketingOS uses a separate JWT, tenant membership and role. `src/proxy.ts` implements the gateway, not the historical `middleware.ts`. Shared API handlers dispatch by credential type. The gateway's bearer allowlist and route authorization are separate controls. Protected MarketingOS **pages** still need ALO admin authentication. There is a development-only JSON fallback for a subset of ALO models, not a production substitute for MySQL.

At baseline, the route allowlist regression test failed, production-like secrets were tracked, several marketing routes trusted role or session state they did not enforce, and the media verifier reported success unconditionally. No production DB, host inventory, restore evidence or current external integration approval was supplied. Production `.env`, credentials, legacy data, assets, applied migrations and release pointers were outside the permitted change surface.

## 8. Database and migration safety

**No schema change, migration, baseline edit, data reset, production seed, or SQL repair.** Six checked-in additive migrations statically match 141 Prisma models, 1,823 scalar column types, keys, indexes, foreign keys, an implicit join and 101 TEXT expression defaults. The unchanged base's hosted CI applied the chain twice on an empty CI MySQL and passed the drift check; that is not an upgrade test against legacy data. New code uses existing tables/fields. Transactions require a working MySQL instance, not the dev JSON store.

Run both disposable integration commands in §12 on MySQL 8, then follow `MIGRATION-RECOVERY-PLAN.md` on a restored copy of the real DB. Compare actual schema, defaults, indexes and exact `_prisma_migrations` checksums; reconcile any differences with the DBA. No production compatibility claim.

## 9. Authentication and security

Browser evidence covers admin password login with the **explicit test-only OTP opt-out**, secure session use, admin logout and denied access without the required identity. It does not verify handset delivery. Keep the production OTP policy and secure cookie/reverse-proxy contract. JWT signing remains HS256; new tokens carry a device ID. Never equate a tenant JWT with an ALO admin session. Review existing privileged memberships/invitations separately: fixing future grants does not undo earlier grants.

Source review included the public-path matcher, same-origin checks, bearer dispatch, Prisma call sites, HTML/SVG rendering, vault and outbound fetch utilities. It is not a penetration test or proof of absence of SQL injection, XSS, CSRF or SSRF. In particular, `src/lib/ssrf.ts` is **not** a guarantee for callers that fetch independently. The advisory scan remains red (§15).

## 10. AI and integration verification

`src/lib/{ai,local-models,external-ai}.ts` contain the local-first ALO path, bounded inference budgets and opt-in external content-draft paths. MarketingOS also has its own agent runtime, provider registry, AI chain, voice and workforce adapters. They are not one unified policy surface. Unit tests cover configured/unconfigured status, gateway/credential separation, external-fallback policy and limits. No Ollama model inference on the target server, ComfyUI job, cloud model result, voice clone, real call, SMS, OAuth exchange, SMTP delivery or Postiz publish was verified. A rule-based draft or simulated transport is not delivery. Retain human approval on publishing/high-impact outputs.

## 11. Media pipeline verification

The bundled Linux FFmpeg and FFprobe executed on this host. Used repository-owned PNG input, bundled Hind Siliguri font, built-in formant WAV (not Piper or eSpeak), Bengali caption text, SRT and temporary directories. Smoke clip had H.264 video and AAC audio. In a second test, the real upload handler generated a **2 s, 714 × 1268** draft, the gallery returned it, the video handler served a byte range and the subtitle handler returned the caption. An invalid second image produced 415 and no leftover job directory. No production media or user photo was used.

Not verified: Bengali typography by native-reader visual inspection, natural-voice quality, peak memory under concurrent renders, all image formats, maximum-size batches, VPS CPU compatibility, or live proxy transfers. Nginx's example 25 MB cap and the application's larger batch allowance need reconciliation. Limits after multipart parsing are not proof of bounded ingress memory.
